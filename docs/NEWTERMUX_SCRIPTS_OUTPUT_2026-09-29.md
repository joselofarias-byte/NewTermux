# Scripts, componentes y salidas largas

Esta rama parte de la punta de `agent/newtermux-extra-key-colors-20260928` (PR #27). No modifica `main` ni publica APK.

- **Más → Mis scripts**: crear, editar, ejecutar y eliminar archivos `.sh` en `$HOME/.newtermux/scripts`. Los nombres admiten letras ASCII, números, `-` y `_`. Ejecutar pasa el archivo a `bash` en la sesión actual. Estos archivos quedan dentro de HOME para su respaldo con TBM.
- **Más → Instalar componentes y PRoot**: comandos confirmados para `proot-distro`, Debian, Git/SSH, Python, Node.js, Go y compilación. Se ejecutan en la sesión actual; `proot-distro install debian` requiere instalar antes `proot-distro`.
- **Harness IA**: ahora vive en un submenú propio dentro de **Instalar componentes y PRoot**. La primera opción, **Un toque · preparar NewTermux**, instala/actualiza e inicia 9router-go, prepara Debian PRoot, instala/actualiza Antigravity, Codex y OpenCode, fusiona de forma no destructiva la configuración de OpenCode para usar `9router/free-best`, intenta instalar TBM sólo si ya pasó su gate explícito y ejecuta una verificación final. Si el JSON previo de OpenCode es inválido, lo preserva como backup antes de crear uno válido. La operación es re-ejecutable y no inicia sesión ni importa credenciales. También queda el submenú de **9router-go** con instalar/actualizar, iniciar, ver estado y detener. NewTermux administra una copia separada del fork en `$HOME/.newtermux/sources/9router-go`, compila el binario nativo y lo instala en `$PREFIX/bin/9router-go`; por defecto escucha en `127.0.0.1:20128` y expone las rutas virtuales `free-best` / `free`. Antigravity, Codex y OpenCode siguen aislados en Debian PRoot. Los scripts incluidos no contienen ni copian credenciales.
- **TBM**: aparece como menú propio **Más → TBM · respaldo y restauración**. La instalación automática queda cerrada hasta que `joselofarias-byte/TBM-Recovery-Master` publique una release **no-prerelease** cuyo cuerpo contenga `NEWTERMUX_READY=1`. Cuando exista, NewTermux descarga `tbm`, `tbm-panel` y `SHA256SUMS.txt` mediante `gh`, verifica SHA-256 y los instala en `$PREFIX/bin`. Como el repo es privado, requiere una sesión válida de `gh`; si falta durante **Un toque**, TBM se omite sin hacer fallar el resto. Backup y restore jamás se lanzan automáticamente: se abren desde `tbm-panel`.
- **Mis scripts**: admite carpetas anidadas, crear/mover/renombrar scripts y carpetas, y color persistente por script/carpeta. La metadata visual se guarda en `$HOME/.newtermux/scripts/.colors.json`, dentro de HOME para que TBM también la conserve.
- **Personalizar controles**: los colores de Limpiar, Copiar, Pegar+↵, ESC, Y, TAB, N, CTRL, ENTER y el grupo de cuatro direccionales se pueden cambiar con el selector HSV/RGB existente. Se guardan en SharedPreferences y la paleta por defecto pasa a tonos pastel oscuros. Las cuatro direccionales comparten siempre un único color configurable.
- **Más → Guardado automático de salidas**: umbral de líneas configurable; `0` desactiva (valor inicial). Al alcanzar el umbral, se crea `Descargas/NewTermux/NewTermux-salida-*.log.gz` con la salida desde el inicio de esa sesión y se siguen anexando miembros gzip completos. Se captura el flujo PTY, incluidos códigos ANSI y potencialmente datos privados; no se puede distinguir la salida de cada comando dentro de un shell. Límite de 32 MiB de datos por sesión, con marcador de truncamiento. Las sesiones anteriores a activar la opción sólo pueden registrarse desde el momento de activación.

El archivo comprimido es un registro del flujo de la terminal, no una transcripción limpia. La exportación manual TXT del historial visible sigue disponible.
